### Webhook

A Webhook sends an HTTPS endpoint each change to holds, reservations and the inventory they draw on -- resources, calendars, calendar events and availability -- as a signed CloudEvent: how a payment service learns a hold lapsed, or a booking layer that a reservation was confirmed or a court was closed for maintenance, without polling.  Changes are read from the records themselves, not announced by the writes, so a change cannot be lost to a crash between a write and its announcement. The price is coalescing: two transitions of one record in quick succession may arrive as one event carrying the later state. Every event carries the whole record, so a receiver acts on what is, not on a diff.

| Field | Type | Behavior | Description |
| --- | --- | --- | --- |
| `name` | `string` | `IDENTIFIER` | The webhook name. Format: webhooks/{webhook} |
| `display_name` | `string` | `OPTIONAL` | Human-readable name, for the operator's own reference. |
| `uri` | `string` | `REQUIRED` | The endpoint each event is POSTed to. HTTPS, except to a loopback host when the server allows insecure endpoints for development. Required on create; an update that leaves it out keeps the current one. |
| `event_types` | `repeated string` | `OPTIONAL` | The event types sent, e.g. "freebusy.reservation.confirmed" or "freebusy.event.deleted". Empty sends every type. A type is "freebusy.<record>.<what happened>": holds are active, released, expired and converted; reservations pending, confirmed, cancelling, cancelled, failed, rescheduling and rescheduled; resources, calendars, events and availabilities created, updated and deleted. |
| `organizational_unit` | `string` | `OPTIONAL` | Limits events to one site's holds, reservations and resources. Empty sends every site's. Calendars, events and availabilities belong to no site, so a webhook limited to one is not sent them. Format: organizationalUnits/{organizational_unit} |
| `state` | `WebhookState` | `OUTPUT_ONLY` | Whether changes are sent. Set by PauseWebhook and ResumeWebhook; pausing keeps the webhook and its history. |
| `secret` | `string` | `OUTPUT_ONLY` | The key every delivery is signed with, in the Standard Webhooks form: a "whsec_" prefix and the encoded key. Returned by CreateWebhook and RotateWebhookSecret only; every other read leaves it empty. |
| `previous_secret` | `string` | `OUTPUT_ONLY` | The key the secret replaced, which also signs deliveries for a day after a rotation so a receiver can switch keys without dropping one. Never returned. |
| `rotate_time` | `Timestamp` | `OUTPUT_ONLY` | When the secret was last rotated. |
| `create_time` | `Timestamp` | `OUTPUT_ONLY` | Creation timestamp. |
| `update_time` | `Timestamp` | `OUTPUT_ONLY` | Last-modification timestamp. |
| `etag` | `string` | `OUTPUT_ONLY` | Opaque version for optimistic concurrency (AIP-154). |

| Value | Number | Description |

| `WEBHOOK_STATE_ACTIVE` | 1 | Changes are delivered. |
| `WEBHOOK_STATE_PAUSED` | 2 | Changes are neither recorded nor delivered for this webhook, and pending deliveries wait. Resuming delivers what was pending, not what changed while paused. |
